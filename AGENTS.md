# Agent rules for Indy-init

- **Tooling is F# only** ([OD-INDY-14](docs/OWNER-DECISIONS-2026-11-01.md)). Write new tooling, checks, generators and scripts in F# (`.fs`, `.fsx`, `.fsproj`). Do not add Python, shell or any other scripting language. The offline suite (`dotnet run --project tools/requirements-compiler/tests -- --offline --source .`) fails on a non-F# script under `tools/` or `.github/`; the only exceptions are the tools still to be ported, listed in that decision. Port one of them only as its own reviewed change.
- **The requirements baseline is generated by `requirements-compiler baseline . <commit>`** ([OD-INDY-15](docs/OWNER-DECISIONS-2026-11-01.md)), never edited by hand.
- **Agents never write, edit or transcribe approval records** (`kickoff/*/approvals.causa.json`) and never self-ratify (RDP-003). The owner records decisions with `tools/owner-freeze.fsx`.
- **AG-13 ("the owner's approving review of the freeze pull request") is met by the owner's package approval record** ([OD-INDY-17](docs/OWNER-DECISIONS-2026-11-01.md)): APR-V4-OWNER-3 for v4, APR-V41-OWNER-4 for v4.1. GitHub does not allow the owner to approve their own pull request. Apply it this way at kickoff (T01) and at acceptance; the tag, main and plan-digest conditions are unchanged.
- **Frozen packages are never edited.** `requirements-compiled/v4` is frozen at tag `indy-init-requirements-v4.0.0`, `requirements-compiled/v4.1` at `indy-init-requirements-v4.1.0`, `requirements-compiled/v4.1.1` at `indy-init-requirements-v4.1.1` and `requirements-compiled/v4.1.2` at `indy-init-requirements-v4.1.2`; CI checks each equals its tagged copy. A change is a new successor package, never an edit.
- **Rehearsal startup order and acceptance levels** ([docs/release-gate-repair/NEXT-REHEARSAL-STARTUP.md](docs/release-gate-repair/NEXT-REHEARSAL-STARTUP.md)). No implementation before the committed initialization checkpoint (`r9.fsx authorize-implementation`); an earlier implementation commit is a process violation (`r9.fsx check-sequencing`). Every suite command must execute before readiness is claimed (`r9.fsx suite-preflight`). Report catalog, competition-scope, full-plan and owner acceptance separately (`r9.fsx acceptance-status`); catalog acceptance is never release acceptance.
- **`requirements-compiled/v4.1.4` is a CANDIDATE** (corrected suite runners, ODR-V414-01..03); it is not frozen and no lock pins it until the owner approves and tags it. 4.1.3 is not used (the withdrawn proposal).
- **A rehearsal builds the whole approved scope** in `docs/rehearsal-010-readiness/scope-manifest.json` (the P0 plan and the catalog), creates every work item in Praxis and commits the scope checkpoint before any application code, and stops only on a `requirements-compiler stop-decision` of `STOP_PERMITTED` or at the deadline ([STARTUP-INSTRUCTIONS.md](docs/rehearsal-010-readiness/STARTUP-INSTRUCTIONS.md)). A passing catalog or a failed release gate is never a reason to stop or to reduce scope.
- **Rehearsal 010 governed verification** ([docs/rehearsal-010-readiness/FINAL-READINESS.md](docs/rehearsal-010-readiness/FINAL-READINESS.md)).
  - `verification/` (journeys J1–J3, the design contract, the harness fixtures) holds owner-controlled acceptance assets. They run from the governed checkout, and a rehearsal never edits or copies them as its own tests.
  - Catalog acceptance is governed only through `requirements-compiler catalog-acceptance` in the Verification gate.
  - A slice merges only on `slice-gate` PASS. Completion is only `completion-gate` COMPLETE.
  - The run clock is bound to the committed T0 record (`--t0-record`, `--deadline-policy`) and is never reset.
  - `tools/r10/adversarial.fsx` and `tools/r10/r9-replay.fsx` must stay green.
