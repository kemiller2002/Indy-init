5. Decision Collection Strategy

Present all outstanding owner decisions together.

Do not conduct seven separate conversations unless the owner requests that format.

For each decision:

* Explain the issue.
* Identify the affected requirements.
* Present the available options.
* State the engineering recommendation.
* Explain the consequence of each option.
* Ask the owner to choose.

The owner may accept the recommendation, select another option, or request changes.

Do not interpret silence as approval.

Do not infer approval from earlier unrelated discussions.

Collect the complete decision set before modifying the frozen verification scope.

This minimizes repeated compilation, validation, and review.

6. Decision Q1: GitHub Authentication and Permissions

Decision ID: DEC-R6-001

Background

Earlier decision DEC-025 established:

* No anonymous application mode.
* GitHub permission fields are advisory.

This conflicts with portions of:

* PF-015-O1.
* PF-015-O2.
* EXT-DATA-005-O1.

Option A: Preserve DEC-025

Continue requiring authentication for catalog access.

Treat repository permission fields as advisory.

Propose authorized scope changes for conflicting obligations.

Option B: Revise DEC-025

Support anonymous read-only access to public catalogs where permitted.

Require authenticated access for protected data and writes.

Implement actual repository and branch permission checks where supported by the provider.

Engineering recommendation

Recommend B.

Separate read authorization from write authorization.

Publicly readable investigation catalogs should not require unnecessary credentials.

Writes must require appropriate authentication and authorization.

Do not infer write permission merely from successful reads.

Do not rely exclusively on advisory permission metadata.

Required safeguards

* Never expose credentials.
* Never write tokens to investigation records.
* Never grant write permissions implicitly.
* Validate repository and branch access.
* Validate paths and manifests.
* Preserve schema and history validation.
* Record permission failures accurately.

Owner action

Ask the owner to select A or B.

Do not apply the recommendation without approval.
