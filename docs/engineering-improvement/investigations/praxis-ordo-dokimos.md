## Smallest-change candidates (extension points)

**B (integration contracts)**
1. **`praxis sync check` multi-ref overlap**: extend `FileUpstreamSynchronization` (`praxis/src/Praxis.Infrastructure/Git/UpstreamSynchronization.fs`, overlap at about line 372) and `UpstreamSyncReport` (`Synchronization.fs:27`) to compute overlap against sibling stream refs (for example `r5/*`), not only upstream. Reuses the existing 30-minute clock, JSON contract and CLI.
2. **Planner `areas` as the stream ownership map**: `ros.json` `planner.areas` and `conflicts` already feed `Graph.collision` (`Graph.fs:208`, `SharedDeclaredPath`/`SharedChangedPath`). A stream becomes a work item or group; ownership becomes `areas`. Adding an enforcing check (changed paths ⊆ areas unless a recorded approval exists) would replace the "coordinator-approved" commit-subject convention. Same predicate as `LocalAgentHandoff` `local-result-resource-escape` (`LocalAgentHandoff.fs:217`).
3. **Ordering**: work-group `MemberDependency` (`WorkGroups.fs:165`, `@merged` milestone) already expresses "consumer starts after producer merged". For requirement order use `ordo verification schedule`.
4. **Interface contracts**: nothing to extend in Praxis, Ordo or Dokimos. Smallest option: keep R5's `interface-manifest.json` staleness test and reference it as a planner `conflicts` / `GroupGates` input.

**G (incremental verification)**
1. **Dokimos `evidence plan`** is the reuse engine. Do not create another one.
2. **Provenance persistence**: add `dokimos.evidence-provenance/1` records to the existing Dokimos `EvidenceStore`/`FileSystemStore` (`EvidenceStore.fs:31,84`; `dokimos-evidence` branch layout), replacing the GitHub Actions cache. Alternatively commit them into R5's existing `evidence/` bundle and manifest. Either reuses an existing store rather than adding a ledger.
3. **Fix the Ordo freshness binding**: `ordo/src/Ordo.Core/VerificationPlanWire.fs:31` `bindingsForPolicy` ignores the policy. Map `content-addressed` to `evidenceIdentity` (Dokimos), `per-commit` to `sourceSha`, and `live` to `runId`. This makes Ordo's stale list agree with Dokimos reuse.
4. **Record failing runs too** (R5 glue `Causa.Acceptance/Reuse.fs` `provenance --outcome`) so CONFLICTING_PRIOR and independent fail publication work.
5. Register an `evidence.reuse-plan` capability in the next Dokimos release manifest (it is missing from 0.8.0's `provides`).
