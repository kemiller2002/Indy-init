## 4. Praxis ordering (Phase 4)

- **`r9.fsx authorize-implementation`** refuses until, in order:
  1. Conditor initialized the repository and governance is applied;
  2. the catalog manifest is current (`praxis requirements manifest check`) and `praxis validate` passes;
  3. the work items exist in Praxis;
  4. every work item names requirements and obligations that exist, and every in-scope obligation is linked (`.echelon/r9-work-plan.json`);
  5. every suite binding an in-scope obligation can execute;
  6. the specification, suite and acceptance preflights passed.

  It then writes the immutable `.echelon/r9-initialization-checkpoint.json`, with the commit and input digests. Verification evidence is not required; that comes after implementation.
- **`r9.fsx check-sequencing`** reports every commit after the T0 bootstrap and before the checkpoint that changes `src/`, `web/`, `tests/` or build files as a **process violation**. It refuses a checkpoint edited after it was committed. It now runs first in the governed Verification gate.
- **On Rehearsal 009:** 6 violating commits, from `edde38c` (the application) to `33d072d`, and no checkpoint.
