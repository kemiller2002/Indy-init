# Causa Persistence Requirements: Session-Local State and GitHub Commits

Status: normative for Rehearsal 7 and every later Causa build, including the event. Adopted by owner decision ADR-R7-001 ([docs/rehearsal-007/PERSISTENCE-ARCHITECTURE-DECISION.md](rehearsal-007/PERSISTENCE-ARCHITECTURE-DECISION.md)). These are behavioural requirements. They do not describe, and must not be satisfied by reusing, the source code of any earlier rehearsal.

## PERSIST-001: Authority and precedence [P0]
This document is the authority for where Causa keeps investigation state, how it saves to GitHub, and how it reports save state. For Causa it takes precedence over, and supersedes, any persistence, offline, local-durability, synchronization-queue or cross-tab statement in the documents ranked (4) to (7) by ADRP-001, and over the long-term platform documents listed in [docs/rehearsal-007/DEFECT-TRACEABILITY.md](rehearsal-007/DEFECT-TRACEABILITY.md). Where such a statement conflicts with this document, this document holds and the conflict is not a STOP under ADRP-001. The frozen causa-data v1.0.0 storage contract and owner decision OD-INDY-9 still govern paths, file sets, serialization, atomicity and read-back; this document refines them and changes none of them. Acceptance: PAT-14 verifies that the requirements validator finds no conflicting statement in the baseline documents.

## PERSIST-002: Each browser tab holds its own investigation state [P0]
Each browser tab MUST hold its own, independent investigation state in F# WebAssembly memory: the investigations it has loaded, the branch head each was loaded or saved at, its unsaved changes, and its save state. A tab MUST NOT read or write another tab's state. Opening the same investigation in two tabs gives two independent copies; a change in one tab MUST NOT appear in the other until it has been saved to GitHub and the other tab loads it from GitHub. Navigation between routes inside one tab MUST keep that tab's state in memory, so moving between investigations or views never loses unsaved changes. Acceptance: PAT-01 verifies tab independence in a real browser.

## PERSIST-003: No shared browser storage for investigations [P0]
Investigation documents, events, snapshots, manifests, unsaved changes, pending commands, save state, branch heads and write markers MUST NOT be written to localStorage, sessionStorage, IndexedDB, Cache Storage, the Origin Private File System, cookies, a service worker, a shared worker or a BroadcastChannel. Only non-investigation preferences, such as tour dismissal (UI-012) or theme, may use browser storage, and they MUST NOT contain investigation content, repository paths or credentials. Credentials stay memory-only (EXT-DATA-004, OD-INDY-10). The browser's ordinary HTTP cache of the application's static assets is not investigation storage. Acceptance: PAT-01 inspects every browser store after edits and saves and verifies that none holds investigation content, and PAT-13 verifies that the production artifact contains no call that writes investigation content to a browser store.

## PERSIST-004: No cross-tab locking or coordination [P0]
Correctness MUST NOT depend on cross-tab locking or messaging. The application MUST NOT use `navigator.locks` (Web Locks), a storage lease or a cross-tab message channel to coordinate investigation writes. Two tabs that save are two independent GitHub writers, and their concurrency is resolved only by the GitHub rules in PERSIST-007 to PERSIST-013. Acceptance: PAT-11 verifies that every persistence test passes with `navigator.locks` removed from the page, and PAT-13 verifies that the production artifact references no Web Locks API.

## PERSIST-005: GitHub is the authoritative durable store [P0]
The connected GitHub repository branch MUST be the only durable store of Causa investigations. An investigation is opened by reading it from GitHub at a branch head and verifying it as a reader would (causa-data v1.0.0 §11). The tab records the commit it read as the investigation's base head. Branch-head reads MUST bypass HTTP caches, and file reads MUST name the commit they read. Acceptance: PAT-10 verifies that an investigation opened in a new tab equals its last confirmed commit on GitHub.

## PERSIST-006: One atomic commit per save, with an expected head [P0]
Every save MUST publish exactly one GitHub commit through one GraphQL `createCommitOnBranch` mutation, as OD-INDY-9 defines. The commit MUST contain the investigation's events append, manifest and snapshot together. Its `expectedHeadOid` MUST be the branch head the change was decided at, or the head it was rebased onto under PERSIST-009. A save MUST NOT use per-file Contents API writes, a forced ref update, or any write without an expected head. Before sending, the adapter MUST check that the commit changes files only under the investigation's own path prefix (causa-data v1.0.0 §9.4.4). A tab MUST have at most one commit mutation in flight at a time; further save requests in that tab wait in memory until it settles. Acceptance: PAT-02 records every mutation the application sends and verifies each one against this requirement.

## PERSIST-007: A save is confirmed only after GitHub confirms it [P0]
A save is confirmed only when GitHub has returned the new commit for that mutation and a re-read at that commit returns the bytes the save wrote (causa-data v1.0.0 §9.4.3). Only a confirmed save may move the investigation to Saved and advance its base head. Changes made in the tab while the save was in flight MUST remain unsaved after it is confirmed. Acceptance: PAT-02 and PAT-10 verify that Saved appears only after the read-back, and PAT-12 verifies that no other transition reaches Saved.

## PERSIST-008: Detect a stale head [P0]
When GitHub refuses a mutation because the branch head is no longer the expected head, the application MUST classify the answer as a stale head: nothing was written, and the change stays unsaved in memory. It MUST classify each provider answer from its typed content, and MUST keep a stale head distinct from a network failure, an authentication or permission failure, a rate limit and a validation error. A network failure MUST NOT be reported as a stale head or a conflict. Acceptance: PAT-03 verifies each classification with the stateful GitHub fake and against the live test repository.

## PERSIST-009: Rebase automatically over unrelated changes [P0]
After a stale head, the application MUST read the new branch head and compare the investigation's files at the base head and at the new head. When those files are unchanged, the branch moved only for unrelated changes, such as another investigation saved by this tab, another tab or another device. The application MUST then re-verify the remote history, keep the same events, manifest and snapshot, and send the commit again with the new head as `expectedHeadOid`, without asking the user. While it does so, the investigation stays Saving. Acceptance: PAT-04 verifies that a change saves without user action after unrelated commits advance the branch, and that the unrelated commits stay on the branch.

## PERSIST-010: Limit automatic rebases [P0]
One save request MUST make at most three automatic rebase attempts, so it sends at most four commit mutations in total. Every attempt MUST follow a fresh read of the branch head. When the limit is reached, the investigation MUST move to Save failed, with the cause that the repository kept changing, and keep the change unsaved in memory until the user asks to save again. Acceptance: PAT-08 verifies that a branch that advances before every attempt receives no more than four mutations for one save request.

## PERSIST-011: Preserve unsaved changes when the same investigation changed remotely [P0]
When the investigation's own files differ between the base head and the new head, another writer has saved the same investigation, and this is a genuine conflict. This includes another tab of the same user. The application MUST NOT rebase, merge or overwrite automatically. It MUST move the investigation to Conflict and keep every unsaved change unchanged in memory, still visible in the tab. An investigation deleted or rewritten on the branch is also a conflict. Acceptance: PAT-05 verifies that the unsaved change is kept, nothing is sent, and the other writer's commit stays on the branch.

## PERSIST-012: Resolve a genuine conflict only by explicit user choice [P0]
A conflict MUST stay in Conflict until the user chooses a resolution. The application MUST offer three actions: review the differences, reapply my changes to the GitHub version, and discard my changes and load the GitHub version. Reapply MUST load the GitHub version and re-decide each unsaved command, in its original order, through the F# domain engine at that version. Accepted commands become unsaved changes on the new base head; refused commands MUST be listed with the engine's reason and MUST NOT be applied. Reapply MUST NOT save; the user saves the result. Discard MUST ask for confirmation first. The application MUST NOT offer any action that replaces the GitHub version with the tab's version. Acceptance: PAT-05 verifies each action and that no action overwrites the other writer's commit.

## PERSIST-013: Never silently overwrite another commit [P0]
No write may remove, replace or hide a commit made by another writer. The application MUST NOT force-push, reset a ref, delete and recreate files, or write against a head it has not read from GitHub in the current tab session. Every other writer's commit MUST remain reachable from the branch head after any sequence of saves, rebases, reconciliations and conflict resolutions. Acceptance: PAT-02, PAT-04 and PAT-05 verify after each scenario that every commit made by every writer is still reachable from the branch head.

## PERSIST-014: Unique write markers [P0]
Each tab MUST create a random session identifier in memory when it starts. Each commit mutation MUST carry a write marker made of that identifier and a sequence number, as a trailer in the commit message. Markers are audit metadata used only for reconciliation (causa-data v1.0.0 §9.4.5), and MUST be unique across tabs, devices and page loads. Acceptance: PAT-02 verifies marker uniqueness across concurrent tabs and reloads.

## PERSIST-015: Reconcile an unknown commit outcome before retrying [P0]
When a mutation may have reached GitHub but no recognised answer came back, the outcome is unknown. This covers a timeout, a lost response, a dropped connection after sending, and any answer the code does not recognise. The investigation MUST move to Unknown commit outcome and MUST NOT send another mutation for it until reconciliation decides the outcome. Reconciliation reads the branch head and the commits after the expected head. If a commit carries this save's marker and its tree holds the written bytes, the save is confirmed. If a commit carries the marker but the bytes differ, the investigation moves to Save failed and is not reported as saved. If the branch head still equals the expected head and no commit carries the marker, nothing was written, and the save may be sent again within the PERSIST-010 limit. If the head moved and no commit carries the marker, the change was not written and the stale-head rules apply. If the expected head is no longer an ancestor of the branch head, the investigation moves to Save failed with the cause that the branch history was rewritten. If a reconciliation read fails, the investigation stays Unknown commit outcome. Acceptance: PAT-06 verifies every branch of this rule with injected lost answers.

## PERSIST-016: Bounded retries and no tight loops [P0]
Automatic network activity for one save request MUST be bounded. Commit mutations are limited by PERSIST-010. Reconciliation of one unknown outcome MUST make at most three automatic reads, at least 2 seconds, 4 seconds and 8 seconds apart, plus one read each time the browser goes from offline to online; after that it waits for the user to choose Check again. A save that fails before it is sent MUST NOT be retried automatically. Under a network that fails every request, one save request MUST cause at most four commit mutations and at most four reconciliation reads in 60 seconds. Acceptance: PAT-08 counts requests for 60 seconds under total network failure and under constant branch advance.

## PERSIST-017: An already loaded investigation stays visible offline [P0]
When the network is lost, every investigation already loaded in the tab MUST stay visible in every view, from the tab's in-memory projection. An investigation that is not loaded MUST show as unavailable offline, never as empty or missing. Acceptance: PAT-07 verifies that the loaded investigation's views render offline and an unloaded one shows unavailable offline.

## PERSIST-018: Editing while disconnected stays in session memory [P0]
If the application allows edits while disconnected, those edits exist only in the tab's memory and MUST be shown as not saved. While the application knows it is offline, a save request MUST NOT send a mutation; it fails immediately and the investigation shows Offline. There is no offline synchronization queue: after the connection returns, the application MUST NOT replay or send saves automatically, and the changes are saved only by a new save request. Acceptance: PAT-07 verifies that a save requested offline sends no request, shows Offline, and that nothing is sent when the connection returns until the user saves.

## PERSIST-019: Warn before leaving with unsaved changes [P0]
While any investigation in the tab is Unsaved, Saving, Offline, Conflict, Unknown commit outcome or Save failed, the application MUST register a `beforeunload` handler so that browsers which support it warn before the tab is closed, reloaded or navigated away. It MUST remove the handler when every investigation is Saved. In-application actions that would drop unsaved changes, such as disconnecting, switching repository or discarding, MUST ask for confirmation. Acceptance: PAT-09 verifies the leave warning in Chromium and the confirmations in every supported browser.

## PERSIST-020: Unsaved work does not survive browser termination [P0]
Closing, reloading or crashing the tab, or the browser or operating system discarding it, destroys unsaved changes. The application provides no local crash recovery of investigation content, and MUST NOT imply that it does. Safari on iPad may not show a leave warning, so the save-state indicator is the primary safeguard. The Connect screen and the in-application help MUST state that unsaved changes exist only in the current tab and are lost when it closes. After a reload, the tab starts from GitHub. Acceptance: PAT-09 verifies the statement is present and reachable by keyboard and screen reader, and PAT-10 verifies that a reload shows only confirmed GitHub state.

## PERSIST-021: Reopen from GitHub [P0]
Opening an investigation in a new tab, after a reload, or on another device MUST load the latest confirmed commit from GitHub and verify it. The investigation MUST show Saved at that commit. It MUST contain every confirmed save and nothing that was not confirmed. Acceptance: PAT-10 verifies reopening after saves from several tabs.

## PERSIST-022: One save state per investigation [P0]
Each investigation in a tab MUST have its own save state. A page MUST show the save state of the investigation it displays, never another investigation's. A workspace-level summary MAY count the investigations in each state, but MUST NOT state a fact that contradicts them. Acceptance: PAT-02 and PAT-05 verify, with two investigations changed in one tab, that each page shows its own state.

## PERSIST-023: Truthful save state is structural [P0]
The save state MUST be computed by one F# state machine, and the user interface MUST render only that machine's projection. Saved MUST be constructible only from a confirmation produced by the PERSIST-007 read-back. Adapters, view code and test fixtures in the production build MUST NOT be able to construct it. Every illegal input to the machine MUST fail closed with a typed fault and leave the state unchanged. Acceptance: PAT-12 verifies every state and input pair and verifies that application code cannot construct Saved.

## PERSIST-024: Failure causes are reported truthfully [P0]
Every save-state message MUST state the cause the application actually determined. A network failure is never described as another writer's change. A conflict is never offered for a failure that only needs the network. Discard is offered only in Conflict and after an explicit request. Acceptance: PAT-07 verifies, with the network failing on the rebase path, that the investigation shows Offline or Unknown commit outcome and never Conflict, and PAT-14's message check rejects a false cause.

## PERSIST-025: Testable provider boundary [P0]
The GitHub adapter MUST sit behind a provider interface. The acceptance tests MUST run against a stateful GitHub fake that enforces `expectedHeadOid`, keeps real commit ancestry, accepts commits from simulated other writers, and can lose an answer after applying or before applying a mutation. The tests MUST also run against the real GitHub test repository. A fake-only pass MUST NOT be reported as live verification (UI-015, PF-020). Acceptance: PAT-02 to PAT-08 run in both modes, and the live run's evidence names the real commits it created.

## PERSIST-026: Built from these requirements [P0]
Rehearsal 7 MUST implement this persistence architecture during its timed build, from these requirements, the frozen storage contract and published Echelon libraries in the approved release set. It MUST NOT copy, vendor, translate or adapt application source code, tests or scripts from Causa or any earlier rehearsal repository (indy-init-rehearsal-001 to indy-init-rehearsal-006). Earlier rehearsals are historical evidence about failures, not code to reuse. A published library MUST NOT be used to store investigation content in the browser, whatever its features. Acceptance: PAT-13 verifies that no source file in the candidate copies a file from an earlier rehearsal, and the independent review verifies the build's provenance.

## PERSIST-030: Forma save-state indicator [P0]
Every displayed investigation MUST show a save-state indicator in its header, built from Forma components: a Forma status lozenge for the state, Forma operation status for the explanation and actions of Unknown commit outcome and Save failed, Forma conflict review for Conflict, and Forma freshness for the time of the last confirmed save. Colours MUST come from semantic Forma theme tokens (UI-016). The indicator MUST show exactly one of seven states: Saved, Unsaved, Saving, Offline, Conflict, Unknown commit outcome and Save failed. Each state MUST be named in text and marked with the lozenge glyph, never by colour alone. Text MUST meet 4.5:1 contrast and the indicator's non-text marks 3:1. A change of state MUST be announced through a polite status live region; Conflict, Unknown commit outcome and Save failed MUST be announced assertively. The indicator MUST stay visible and readable at 320px width, at 200% text size and in iPad portrait and landscape. Acceptance: PAT-15 verifies every state's rendering, contrast, announcement and reflow, with screenshots of each state from the deployed exact SHA.

## PERSIST-031: Meaning of each save state [P0]
The seven states have these entry conditions, words and actions:
- Saved: the last save was confirmed under PERSIST-007 and the tab holds no unsaved change. The lozenge reads "Saved", and the freshness line gives the commit time. No action is offered.
- Unsaved: the tab holds changes that have not been sent, and the application is online. The text says the changes exist only in this tab. The action is Save.
- Saving: a commit mutation is being prepared or is in flight, or an automatic rebase or reconciliation read is running. The text says the change is being saved to GitHub and is not yet confirmed. No save action is offered.
- Offline: the application is offline and the tab holds unsaved changes. The text says the changes exist only in this tab and cannot be saved until the connection returns. Save is offered only after the connection returns.
- Conflict: PERSIST-011 applies. The text says another writer changed this investigation on GitHub, nothing of this tab's change was written, and the tab's changes are kept. The actions are the three of PERSIST-012.
- Unknown commit outcome: PERSIST-015 applies. The text says the save may or may not have reached GitHub and that the application is checking. Save is not offered; Check again is offered after the automatic reads are spent.
- Save failed: GitHub refused the save for a reason other than a stale head, the rebase limit was reached, or a reconciliation found a mismatch or rewritten history. The text names the cause and says the changes are kept in this tab. The action is Retry when a retry can succeed, or Reconnect when the credential was refused.
When the application is offline and the tab holds no unsaved change, the indicator stays Saved and the workspace header shows that the application is offline. Acceptance: PAT-15 verifies each state's entry condition, words and actions, and PAT-12 verifies that the machine reaches each state only from its entry condition.

## PERSIST-032: No false persistence claims [P0]
The words saved, synced, stored and safe MUST NOT describe an investigation in any state other than Saved. The interface MUST NOT say that a change is saved locally, saved on this device, queued, or will be saved later. Offline and Unsaved MUST say that the change exists only in this tab. Retry and Check again MUST be shown only when they perform a real action (UI-010). Acceptance: PAT-15 verifies the text of every state against this list, and PAT-14 verifies that no requirement or interface copy in the candidate uses a forbidden phrase.

## PERSIST-033: Workspace connection and unsaved summary [P0]
The workspace header MUST show the connection state (EXT-DATA-007) and, when any investigation in the tab is not Saved, the number of such investigations with a link to each. The header MUST NOT contradict the investigations it summarizes; for example, it never says that the workspace is empty while it holds investigations. Acceptance: PAT-15 verifies the header against the investigations' states in each scenario of PAT-02, PAT-05 and PAT-07.

## PERSIST-040: PAT-01 independent browser-tab state [P0]
The Rehearsal 7 agent MUST implement and run, during the timed build, a browser test that opens the same investigation in two tabs of one browser profile. It edits it differently in each tab without saving. The test MUST verify that neither tab shows the other's change, that each tab's indicator is Unsaved, and that every browser store holds no investigation content. It then saves in the first tab and verifies that the second tab is unchanged until it loads from GitHub. Acceptance: the test passes in Chromium and WebKit on the candidate SHA. It covers PERSIST-002 and PERSIST-003.

## PERSIST-041: PAT-02 concurrent GitHub commits [P0]
The Rehearsal 7 agent MUST implement and run a test in which at least three tabs save changes to different investigations at the same moment, against the stateful fake and against the live test repository. The test MUST verify that every change is confirmed exactly once and that each tab shows its own investigations' states. It also verifies that every mutation is one `createCommitOnBranch` with an expected head and paths inside its investigation, that markers are unique, and that every commit stays reachable from the branch head. Acceptance: the test passes in both modes on the candidate SHA. It covers PERSIST-006, PERSIST-007, PERSIST-013, PERSIST-014, PERSIST-022 and PERSIST-025.

## PERSIST-042: PAT-03 stale head rejection [P0]
The Rehearsal 7 agent MUST implement and run a test in which another writer advances the branch after the tab read it. The test MUST verify that GitHub refuses the tab's mutation for the stale head, that the application classifies it as stale and not as a network, permission, rate-limit or validation failure, and that nothing of the tab's change was written. The same test injects each of those other failures and verifies its own classification. Acceptance: the test passes on the candidate SHA. It covers PERSIST-008.

## PERSIST-043: PAT-04 automatic rebase of unrelated changes [P0]
The Rehearsal 7 agent MUST implement and run a test in which commits to another investigation, and to a file outside the investigations, advance the branch before the tab saves. One of those commits is made by the same tab. The test MUST verify that the save is confirmed without user action, through at most three rebase attempts, and that the unrelated commits remain on the branch unchanged. Acceptance: the test passes against the fake and live on the candidate SHA. It covers PERSIST-009 and PERSIST-013.

## PERSIST-044: PAT-05 same-investigation conflict preservation [P0]
The Rehearsal 7 agent MUST implement and run a test in which a second tab saves the same investigation that the first tab has changed. The test MUST verify that the first tab shows Conflict, that its unsaved changes are kept and visible, and that no mutation is sent until the user resolves it. It verifies each PERSIST-012 action: review shows both versions; reapply re-decides the commands through the engine and lists refused ones; discard asks for confirmation. After every action, the second tab's commit is still reachable from the branch head. Acceptance: the test passes on the candidate SHA. It covers PERSIST-011, PERSIST-012, PERSIST-013 and PERSIST-022.

## PERSIST-045: PAT-06 unknown commit reconciliation [P0]
The Rehearsal 7 agent MUST implement and run a test that loses the answer to a mutation in each of two ways: after GitHub applied it and before GitHub applied it. The test MUST verify that the investigation shows Unknown commit outcome and that no second mutation is sent before reconciliation. Applied must end Saved after the read-back. Not applied with an unchanged head must be sent again within the limit and end Saved. Not applied with a moved head must follow the stale-head rules. A marker with different bytes, a rewritten history and a failing reconciliation read each have their own case and expected state. Acceptance: the test passes on the candidate SHA. It covers PERSIST-015.

## PERSIST-046: PAT-07 offline save failure [P0]
The Rehearsal 7 agent MUST implement and run a browser test that takes the browser offline with an investigation loaded, edits it, and requests a save. The test MUST verify that the loaded investigation's views still render, that an unloaded investigation shows unavailable offline, and that the save sends no request and shows Offline. When the browser comes back online, nothing is sent until the user saves. A second case fails the network only on the rebase path; the test verifies that the investigation shows Unknown commit outcome or Offline, never Conflict, and that Discard is not offered. Acceptance: the test passes in Chromium and WebKit on the candidate SHA. It covers PERSIST-017, PERSIST-018 and PERSIST-024.

## PERSIST-047: PAT-08 no uncontrolled retry loops [P0]
The Rehearsal 7 agent MUST implement and run a test that counts every request the application sends for one save request for 60 seconds. It runs in three conditions: every request fails as if offline, every mutation's answer is lost, and the branch advances before every attempt. The test MUST verify at most four commit mutations and at most four reconciliation reads in each condition. The final state must be Offline, Unknown commit outcome or Save failed, as PERSIST-031 defines, and never Saving. Acceptance: the test passes on the candidate SHA. It covers PERSIST-010 and PERSIST-016, and is the regression test for R6-D-003.

## PERSIST-048: PAT-09 navigation with unsaved changes [P0]
The Rehearsal 7 agent MUST implement and run a browser test that creates an unsaved change and then attempts to close the tab, reload it, and follow an external link. The test MUST verify that a leave warning is requested in each case where the browser supports it, and that none is requested once every investigation is Saved. Acceptance: the test passes on the candidate SHA in Chromium, with the confirmations and the statement also verified in WebKit. It covers PERSIST-019 and PERSIST-020.

## PERSIST-049: PAT-10 successful reopening from GitHub [P0]

The test MUST verify that each shows Saved at the latest commit, contains every confirmed change, and contains no change that was never confirmed. A tab reloaded with unsaved changes shows only the confirmed GitHub state. Acceptance: the test passes against the fake and live on the candidate SHA. ## PERSIST-055: Execution of the persistence acceptance tests [P0]
Every PAT test MUST run in CI on the candidate SHA, and its result MUST be recorded in the acceptance ledger under its own identity. A PAT test that was not implemented or not run is NOT_RUN, and one that fails is FAIL; neither may be reported as PASS. A test MUST NOT be weakened, skipped or quarantined to make it pass. Acceptance: the final acceptance run verifies that the ledger holds a result for each of PAT-01 to PAT-15.
