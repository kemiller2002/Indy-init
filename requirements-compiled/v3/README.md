## Amendments

An amendment is applied only when it is an authenticated operator change `{obligation_id, action: amend, criterion, rationale}` in the pinned approvals file. Any other amendment fails compilation (V18) and is never applied.

The obligation keeps its baseline text verbatim, so preservation still holds. Its `amendment` states the criterion its bound tests must prove instead. The amendment is copied into the acceptance contract.

`verify-plan` re-checks every amendment against the approvals file it is given. An edited or forged amendment makes the verdict INVALID (`UNAUTHORIZED-AMENDMENT`).

**Limitation, stated rather than hidden:** the approvals file was transcribed by an agent on the owner's instruction. The approvals are authentic only once the owner merges the pull request that adds them (RDP-003).

The curation pins the approvals file by commit `1865da2`. That commit must stay reachable from `main`. **Merge the pull request with a merge commit, not a squash.**

## Derived obligation (UI-015-O2)

UI-015-O2 restates other obligations. Its 11 clauses are each a whole, verbatim phrase of its text. Together with the connectives "Verify", "verify" and "and", they account for every word of it.

**Seven clauses are verified by their constituents:**
- catalog load and replay: EXT-DATA-013-O2;
- keyboard/touch: UI-004-O5, UI-011-O1, UI-011-O3;
- graph text: UI-011-O5;
- command enforcement: UI-004-O1, UI-004-O6;
- save/sync truthfulness: UI-006-O1, UI-006-O2;
- offline/conflict recovery: UI-006-O4, UI-010-O1;
- reflow: UI-011-O2.

**Four clauses are residual**, because no P0 obligation states them:
- the five frozen v1.0.0 fixtures;
- timeline ordering;
- report fidelity;
- startup failure.

UI-015-O2's own bound test proves the residual clauses.

The obligation is verified only when its own categories are covered and every constituent is verified.

## Rebuild

```bash
requirements-compiler --source . --committed-baseline requirements/causa-requirements-baseline-r6.json \
  --curation requirements-compiled/v3/curation --out requirements-compiled/v3 --repo NAME=DIR... [--check]
requirements-compiler plan-readiness --plan requirements-compiled/v3/verification-plan.json \
  --plan-digest 13516e0d5930d30c89e02cbd2aea895afaea1f08358c02538702aea7bcd8a66c
```

The offline suite (`R6ScopeTests`) rebuilds this plan from committed files and checks four things:
- it equals the committed plan;
- it is READY with no permit;
- it is bound exactly as proposed;
- v2 and the frozen baseline are unchanged.

It also runs a negative control for every scope decision.
