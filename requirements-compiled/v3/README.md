## Amendments (mechanism ready, none applied)

An amendment is applied only when it is an authenticated operator change `{obligation_id, action: amend, criterion, rationale}` in the pinned approvals file. Any other amendment fails compilation (V18) and is never applied.

When one applies:
- the obligation keeps its baseline text verbatim, so preservation still holds;
- its `amendment` states the criterion its bound tests must prove instead, and is copied into the acceptance contract;
- `verify-plan` re-checks it against the approvals file it is given. An edited or forged amendment makes the verdict INVALID (`UNAUTHORIZED-AMENDMENT`).

Only the operator may write that record (RDP-003). The committed file holds none, so v3 amends nothing. Owner decisions DEC-R6-003 and DEC-R6-004 wait for the owner's records (see `kickoff/rehearsal-006/OWNER-DECISIONS.md`).

The curation pins the approvals file by commit `efa5a33`. That commit must stay reachable from `main`. **Merge the pull request with a merge commit, not a squash.**

## Derived obligation (UI-015-O2)

UI-015-O2 restates other obligations. Its 11 clauses are each a whole, verbatim phrase of its text. Together with the connectives "Verify", "verify" and "and", they account for every word of it. The compiler fixes the vocabulary of allowed connectives; the curation cannot extend it.

| Clause | Constituents (each must be verified) | Also proven by UI-015-O2's own test |
|---|---|---|
| catalog load and replay | EXT-DATA-013-O2 | yes (direct): the constituent has no browser evidence |
| frozen v1.0.0 fixtures | none | yes (residual) |
| keyboard/touch paths | UI-004-O5, UI-011-O1, UI-011-O3 | no |
| graph textual equivalent | UI-011-O5 | no |
| timeline ordering | UI-003-O1, UI-003-O3 | yes (direct) |
| legal command enforcement | AR-006-O2, UI-004-O1, UI-004-O4, UI-004-O6 | yes (direct) |
| save/sync truthfulness | UI-006-O1, UI-006-O2 | no |
| offline/conflict recovery | UI-006-O4, UI-010-O1 | yes (direct) |
| responsive reflow | UI-011-O2 | no |
| report fidelity | none | yes (residual) |
| startup failure | none | yes (residual) |

UI-015-O2 is verified only when two things hold:
- its own categories are covered;
- every constituent is verified.

The compiler checks that each clause is verbatim and that its constituents are real, in-scope and not derived. It cannot check that a constituent actually states its clause; that is a review judgement (AR-034-O2). Where a constituent proves less than its clause, the clause is marked direct, so a wrong mapping can only add obligations to verify, never remove the own test's duty.

## Rebuild

```bash
requirements-compiler --source . --committed-baseline requirements/causa-requirements-baseline-r6.json \
  --curation requirements-compiled/v3/curation --out requirements-compiled/v3 --repo NAME=DIR... [--check]
requirements-compiler plan-readiness --plan requirements-compiled/v3/verification-plan.json \
  --plan-digest 8ef1c8dca656e515f63ff287d560a9b76ffbaffc0e5fa27d81f6637b3aa46e41
```

The offline suite (`R6ScopeTests`) rebuilds this plan from committed files and checks four things:
- it equals the committed plan;
- it is READY with no permit;
- it is bound exactly as proposed;
- v2 and the frozen baseline are unchanged.

It also runs a negative control for every scope decision.
