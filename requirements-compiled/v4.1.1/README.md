# Compiled package v4.1: implementation efficiency

v4.1 sits on top of [package v4](../v4/README.md). It does not change any requirement, obligation or test binding: it uses v4's verification plan byte for byte, and [preservation-report.json](preservation-report.json) proves this. What v4.1 adds is the material a team would otherwise have to work out during the seven-hour build:

- interfaces;

- state-machine tables;
- GitHub error handling;
- layout rules;
- test grouping;
- the schedule.

## Regenerate

```
requirements-compiler v41 --source . --package requirements-compiled/v4.1 --base requirements-compiled/v4 \
  [--forma-tarball design-system-0.12.0.tgz] [--check] [--bootstrap EMPTY-DIR]
```

CI does six things:

1. Downloads the Forma 0.12.0 npm tarball and verifies its SHA-256.
2. Runs `v41 --check` with that tarball. This regenerates every file, compares it byte for byte, and checks that the committed Forma inventory matches the published package.
3. Builds `contracts/` to typecheck the interface contracts.
4. Checks that each negative control in `contracts/negative/` (a forged `Confirmation`, a read of the credential's token) is refused (FS1093).
5. Runs `v41 --bootstrap` into a git-initialised empty directory (at the event, v4.1.1 instead layers onto the repository `conditor init` created; see AGENT-RULES duty 1; CI also layers onto a recorded Conditor 0.10.18 scaffold) and builds the generated .NET skeleton of the application repository (solution, projects, compile lists, contracts, layout-assertion module, and the NuGet test tooling the owner locked in ODR-V41-07, restored from NuGet; its `package.json` also pins the npm tooling of ODR-V41-07 and ODR-V41-09, which this step does not install; integration's other shared files are added at T10).
6. Runs the executable layout assertions (`layout-tests/run.mjs`, with axe-core 4.14.0 for `axeClean`) in Chromium and WebKit against Forma's pattern pages and the broken fixtures. It then measures the catch rate on every review defect page (`run.mjs --catch-rate`, [layout-tests/catch-rate.mjs](layout-tests/catch-rate.mjs)) and fails on a miss that R41-11 does not disclose or on a conforming page that fails.

The offline test suite also runs the v4.1 negative controls in [V41Tests.fs](../../tools/requirements-compiler/tests/V41Tests.fs).

## Checks

Each check has negative controls in `V41Tests.fs`, which show it rejects a broken input.

| Check | Guards |
|---|---|
| X01 | Every file has exactly one owner, a declared role, and no file holds two owners' tests |
| X02 | Project files, solution, composition, shared configuration, dependency manifests, CI, deployment and `web/` belong to integration. This is a fixed rule in the compiler |
| X03 | Compile order is fixed in advance. Source and test project references are acyclic, and every test file is in a declared test project |
| X04 | Every interface has a complete contract, implemented by one file its producer owns. Producer tests are in the producer's files, and every consumer has a contract test in its own file |
| X05 | Each machine's states and events are exactly the cases of one interface's state and input unions |
| X06 | The error matrix:<br>• covers every required class and timeouts;<br>• never relies on a shared status alone, nor on duplicated evidence;<br>• keeps each class's retries within its bound;<br>• uses tests that verify the class's requirements |
| X07 | The Forma contract names only published custom properties, classes, patterns and breakpoints, and colours only with a requirement source. The inventory matches the package |
| X08 | The telemetry defines every required metric and separates textual conflicts from semantic failures. A missing metric is recorded as null, never inferred |
| X09 | Every plan binding, and every contract, state-machine and unit test, is in exactly one suite |
| X10 | v4's plan, counts and P0 obligations are unchanged |
| X11 | No input or document names an earlier rehearsal's repository or source |
