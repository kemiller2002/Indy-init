## Test bindings (ESO-R6-02)

Every one of the 671 required category checks of the 355 obligations is bound:

- 29 obligations to Praxis process and owner producers (Indy-init#34);
- 372 more tests from `requirements-compiled/v3/proposals/r6-test-bindings.proposed.json`, generated by
  `requirements-compiler propose-test-bindings` from a fixed convention.

The convention is stated in the proposal. **The rehearsal's tests must carry exactly these identities**: the
verifier matches a ledger entry's `testId` to a binding character for character. For example, a deterministic browser
test for UI-017-O2 is `playwright:acceptance/UI-017.spec.js > UI-017-O2 [chromium]`, and a live .NET test for
PF-015-O1 is `dotnet:Causa.Acceptance.Live.PF015Tests.PF-015-O1`.

A bound test proves nothing by being named. An obligation is verified only by evidence the acceptance run produces.

## Owner decisions and reviews on GitHub (ESO-R6-05)

The acceptance job reads decisions from review bodies, one per line:

```
Decision: DEC-R6-KICKOFF
Decision: DEC-R6-RUN-001 paths: src/engine/Replay.fs, AR-024
Decision: final-disposition
```

Because the owner's and the reviewer's reviews share the login `kemiller2002`, the verifier keeps only the **latest**
review per login on each pull request.

- Post owner decisions and the reviewer's attestation on separate pull requests, or make the latest review carry every
  decision the pull request needs.
- A later CHANGES_REQUESTED or DISMISSED review on a pull request withdraws what that pull request's earlier approval
  proved. A COMMENTED review changes nothing.

## Acceptance job

`acceptance-process.yml` is a workflow template. At kickoff:

1. Copy it to the rehearsal repository's `.github/workflows/`.
2. Set `INDY_INIT_COMMIT` to the Indy-init commit carrying these records. The job refuses to run until this is
   pinned.

The job then:

1. fetches every pull request's reviews in its own run;
2. converts them with `requirements-compiler review-attestations`;
3. runs `verify-process` against the candidate's Praxis log, trusting only its own run id.

The full acceptance verdict passes the same inputs to `verify-plan`, which computes the process assessment itself. It must also pass the review records of tags removed from obligations, `--review-tag-changes review-tag-changes.json` (`indy-init.review-tag-changes/1`, R5A-001-04). The file is the reviewer's, committed in the rehearsal repository. Without it, a test a review removed would still count:

```
--process-plan-digest <plan digest> --process-rules <rules> --process-rules-sha256 <rules sha>
--process-repo <candidate checkout> --process-attestations attestations.json --process-trusted-run-id <run id>
```
